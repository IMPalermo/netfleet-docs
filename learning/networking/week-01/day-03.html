Ethernet, MAC Address and ARP

Week 01 | Day 03

Ethernet، MAC Address و ARP

اهداف یادگیری

  • مفهوم Ethernet و Frame را بشناسی.
  • MAC Address را از IP Address تفکیک کنی.
  • نقش Switch را توضیح بدهی.
  • عملکرد ARP را در شبکه محلی درک کنی.
  • اطلاعات واقعی سیستم را با PowerShell بررسی کنی.

1. Ethernet چیست؟

Ethernet یکی از فناوری‌های اصلی شبکه‌های محلی سیمی است.

Ethernet مشخص می‌کند دستگاه‌ها چگونه داده را در قالب Frame منتقل کنند و چگونه از آدرس‌های MAC برای شناسایی رابط‌های شبکه استفاده شود.

استانداردهای Ethernet در خانواده IEEE 802.3 تعریف شده‌اند.

2. MAC Address

هر رابط شبکه برای ارتباط در لایه دوم از یک آدرس MAC استفاده می‌کند.

نمونه:

A4:5E:60:12:34:56

MAC Address معمولاً به شکل ۴۸ بیتی نمایش داده می‌شود.

دو بخش اصلی آن: - بخش ابتدایی: شناسه سازنده یا OUI - بخش انتهایی: شناسه اختصاص داده‌شده به رابط

نکته مهم: MAC Address همیشه یک شناسه ثابت و قابل اعتماد برای شناسایی فیزیکی دستگاه نیست. سیستم‌عامل‌ها می‌توانند از MAC تصادفی یا تغییر یافته استفاده کنند.

3. IP در برابر MAC

ویژگی MAC IP
لایه Data Link Network
کاربرد ارتباط محلی آدرس‌دهی و مسیریابی
نمونه AA:BB:CC:11:22:33 192.168.1.10
نوع آدرس رابط شبکه آدرس منطقی

یک بسته IP هنگام عبور از روترها می‌تواند در فریم‌های متفاوت قرار بگیرد. آدرس MAC فریم در هر شبکه محلی ممکن است تغییر کند، اما IP مبدأ و مقصد معمولاً تا رسیدن به مقصد نهایی حفظ می‌شوند، مگر اینکه NAT یا سازوکارهای دیگری آن‌ها را تغییر دهند.

4. Ethernet Frame

یک فریم Ethernet معمولی شامل بخش‌های زیر است:

بخش وظیفه
Destination MAC آدرس MAC مقصد
Source MAC آدرس MAC مبدأ
EtherType مشخص کردن نوع Payload
Payload داده
FCS بررسی خطا در فریم

سوئیچ‌ها از اطلاعات لایه دوم برای انتقال فریم‌ها استفاده می‌کنند.

5. Switch چگونه کار می‌کند؟

سوئیچ معمولاً جدول MAC Address یا CAM Table دارد.

فرض کن: - کامپیوتر A به Port 1 متصل است. - کامپیوتر B به Port 2 متصل است. - کامپیوتر C به Port 3 متصل است.

وقتی فریمی از کامپیوتر A دریافت می‌شود، سوئیچ MAC مبدأ را یاد می‌گیرد و آن را به Port 1 نسبت می‌دهد.

سپس MAC مقصد را در جدول جست‌وجو می‌کند.

اگر مقصد را بشناسد، فریم را به پورت مربوطه می‌فرستد. اگر مقصد ناشناخته باشد، فریم را در همان VLAN به سایر پورت‌های مناسب Flood می‌کند.

6. ARP چیست؟

در شبکه IPv4، دستگاه برای ارسال فریم به یک IP محلی معمولاً به MAC مقصد نیاز دارد.

ARP این نگاشت را پیدا می‌کند.

مثال:

Who has 192.168.1.1?
Tell 192.168.1.10

دستگاهی که IP برابر 192.168.1.1 دارد، پاسخ می‌دهد و MAC خود را اعلام می‌کند.

نتیجه در ARP Cache ذخیره می‌شود تا برای هر ارتباط دوباره درخواست ارسال نشود.

نکته مهم درباره Gateway

اگر مقصد IP خارج از Subnet محلی باشد، سیستم معمولاً MAC مربوط به Default Gateway را پیدا می‌کند، نه MAC سرور مقصد نهایی را.

7. آزمایش عملی

مشاهده کارت‌های شبکه

Get-NetAdapter

مشاهده MAC Address

Get-NetAdapter | Select-Object Name, MacAddress, Status, LinkSpeed

مشاهده جدول ARP

arp -a

مشاهده جدول همسایه‌ها

Get-NetNeighbor -AddressFamily IPv4

ایجاد ترافیک و بررسی مجدد

ابتدا:

ping 8.8.8.8

سپس:

arp -a

بررسی کن آیا MAC مربوط به Gateway در جدول مشاهده می‌شود یا خیر.

8. آزمایش Wireshark

Wireshark را اجرا کن و روی Interface فعال Capture بگیر.

فیلتر:

arp

سپس در PowerShell:

arp -d *
ping 192.168.1.1

به‌جای IP نمونه، آدرس واقعی Gateway خودت را قرار بده.

در Wireshark به این موارد توجه کن: - ARP Request - ARP Reply - Sender IP - Sender MAC - Target IP

حذف ARP Cache فقط برای آزمایش انجام می‌شود و ممکن است برای چند لحظه ارتباط محلی را تحت تأثیر قرار دهد.

9. ارتباط با Automation

در پروژه NetFleet می‌توانیم: - MAC Address تجهیزات را جمع‌آوری کنیم. - تغییرات جدول ARP را بررسی کنیم. - دستگاه‌های جدید شبکه را شناسایی کنیم. - وضعیت Interfaceها را مانیتور کنیم.

البته ARP به‌تنهایی ابزار قطعی شناسایی دستگاه نیست.
