TCP, UDP, DNS and DHCP

Week 01 | Day 05

TCP، UDP، DNS و DHCP

اهداف یادگیری

  • تفاوت TCP و UDP را درک کنی.
  • Port Number و Socket را بشناسی.
  • فرآیند DNS Resolution را توضیح بدهی.
  • DHCP و فرآیند تخصیص IP را بشناسی.
  • اتصال‌های واقعی سیستم را با PowerShell بررسی کنی.

1. Transport Layer

لایه Transport ارتباط بین برنامه‌های در حال اجرا روی دستگاه‌های مختلف را مدیریت می‌کند.

دو پروتکل اصلی این لایه:

  • TCP
  • UDP

هر دو از Port Number برای شناسایی سرویس‌ها و برنامه‌ها استفاده می‌کنند.

2. TCP چیست؟

TCP یک پروتکل Connection-oriented است.

ویژگی‌های مهم: - برقراری ارتباط قبل از انتقال داده - ترتیب‌دهی داده‌ها - تأیید دریافت - ارسال مجدد داده‌های ازدست‌رفته - کنترل جریان و کنترل ازدحام

TCP Three-Way Handshake

برقراری اتصال TCP معمولاً با سه مرحله انجام می‌شود:

  1. Client یک SYN ارسال می‌کند.
  2. Server با SYN-ACK پاسخ می‌دهد.
  3. Client یک ACK ارسال می‌کند.

پس از این فرآیند، اتصال آماده انتقال داده است.

TCP برای سرویس‌هایی مانند HTTPS، SSH و بسیاری از ارتباطات مدیریتی استفاده می‌شود.

3. UDP چیست؟

UDP بدون برقراری اتصال اولیه داده را ارسال می‌کند.

ویژگی‌ها: - سربار کمتر - عدم تضمین تحویل - عدم تضمین ترتیب بسته‌ها - مناسب برای کاربردهایی که تأخیر مهم است

نمونه کاربردها: - DNS در بسیاری از Queryها - VoIP - بازی‌های آنلاین - برخی ارتباطات ویدئویی

نکته: DNS فقط UDP نیست. برای پاسخ‌های بزرگ‌تر، Zone Transfer و شرایط دیگر از TCP نیز استفاده می‌شود.

4. مقایسه TCP و UDP

ویژگی TCP UDP
اتصال اولیه دارد ندارد
تضمین تحویل با مکانیزم‌های انتقال ندارد
ترتیب داده مدیریت می‌شود تضمین نمی‌شود
سربار بیشتر کمتر
کاربرد نمونه HTTPS، SSH Voice، بعضی DNS Queryها

هیچ‌کدام همیشه بهتر نیستند. انتخاب به نیاز برنامه بستگی دارد.

5. Port Number

Port Number یک مقدار ۱۶ بیتی است.

چند پورت شناخته‌شده:

Port Protocol / Service
22 SSH
53 DNS
67/68 DHCP
80 HTTP
123 NTP
443 HTTPS

پورت‌ها در سه دسته کلی قرار می‌گیرند: - Well-known: 0 تا 1023 - Registered: 1024 تا 49151 - Dynamic/Private: 49152 تا 65535

یک ارتباط شبکه‌ای معمولاً با IP مبدأ، Port مبدأ، IP مقصد، Port مقصد و Protocol قابل شناسایی است.

6. DNS چیست؟

DNS نام دامنه را به اطلاعاتی مانند IP Address تبدیل می‌کند.

مثال:

example.com -> IP Address

فرآیند ساده‌شده: 1. برنامه درخواست نام دامنه می‌دهد. 2. سیستم Cache را بررسی می‌کند. 3. در صورت نیاز از DNS Resolver سؤال می‌کند. 4. Resolver پاسخ را پیدا می‌کند. 5. نتیجه به سیستم برمی‌گردد.

انواع رکوردهای رایج:

Record کاربرد
A نام به IPv4
AAAA نام به IPv6
CNAME نام مستعار
MX Mail Server
TXT متن و اطلاعات اعتبارسنجی
NS Name Server
PTR Reverse DNS

7. DHCP چیست؟

DHCP تنظیمات شبکه را به شکل خودکار در اختیار Client قرار می‌دهد.

اطلاعات متداول: - IP Address - Subnet Mask یا Prefix - Default Gateway - DNS Server - Lease Time

فرآیند DORA

  1. Discover: کلاینت دنبال DHCP Server می‌گردد.
  2. Offer: سرور یک پیشنهاد ارسال می‌کند.
  3. Request: کلاینت پیشنهاد را درخواست می‌کند.
  4. Acknowledge: سرور تخصیص را تأیید می‌کند.

این فرآیند معمولاً با پیام‌های Broadcast و UDP انجام می‌شود.

8. آزمایش عملی PowerShell

بررسی DNS

nslookup example.com

بررسی جزئیات DNS

Resolve-DnsName example.com

بررسی پورت TCP

Test-NetConnection example.com -Port 443

مشاهده اتصال‌های فعال

Get-NetTCPConnection

مشاهده Processهای مرتبط با اتصال

Get-NetTCPConnection |
Select-Object LocalAddress, LocalPort, RemoteAddress, RemotePort, State, OwningProcess

بررسی Process با PID

Get-Process -Id 1234

به‌جای 1234 مقدار PID واقعی را قرار بده.

مشاهده تنظیمات DHCP

Get-NetIPConfiguration

مشاهده وضعیت DHCP رابط‌ها

Get-NetIPInterface -AddressFamily IPv4 |
Select-Object InterfaceAlias, Dhcp, ConnectionState

9. تمرین عیب‌یابی

سناریو: یک سیستم به اینترنت دسترسی ندارد.

به ترتیب این موارد را بررسی کن:

  1. آیا کارت شبکه فعال است؟
  2. آیا IP معتبر دریافت شده است؟
  3. آیا Gateway قابل دسترسی است؟
  4. آیا ارتباط با IP عمومی برقرار می‌شود؟
  5. آیا DNS نام دامنه را Resolve می‌کند؟
  6. آیا پورت سرویس مقصد قابل دسترسی است؟

دستورات پیشنهادی:

Get-NetAdapter
Get-NetIPConfiguration
ping <gateway-ip>
ping 1.1.1.1
nslookup example.com
Test-NetConnection example.com -Port 443

توجه: موفقیت یا شکست Ping به‌تنهایی اثبات‌کننده وضعیت کل سرویس نیست. ممکن است ICMP مسدود باشد ولی TCP کار کند.

10. ارتباط با Network Automation

این مفاهیم در اتوماسیون شبکه کاربرد مستقیم دارند:

  • بررسی دسترسی به سرویس‌ها با TCP
  • مانیتورینگ DNS
  • بررسی DHCP و IP Assignment
  • جمع‌آوری اطلاعات اتصال‌ها
  • ساخت گزارش از وضعیت سرویس‌های شبکه

در مراحل بعدی NetFleet، از Python برای اجرای تست‌های اتصال و تحلیل نتایج استفاده خواهیم کرد.
