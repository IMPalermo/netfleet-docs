Introduction to Computer Networks

Week 01 · Day 01

Understanding computer networks, communication architecture, network devices and practical connectivity testing

جلسه اول: آشنایی با شبکه‌های کامپیوتری

1. اهداف یادگیری

در پایان این جلسه باید بتوانی:

  • مفهوم شبکه کامپیوتری و کاربرد آن را توضیح بدهی.
  • تفاوت ارتباط محلی و ارتباط بین شبکه‌ها را درک کنی.
  • اجزای اصلی یک شبکه را شناسایی کنی.
  • نقش Client، Server، Switch، Router و Access Point را توضیح بدهی.
  • مسیر تقریبی ارسال داده از کامپیوتر خودت به یک سرور اینترنتی را تشریح کنی.
  • با ابزارهای خط فرمان، وضعیت اتصال سیستم را بررسی کنی.
  • مشکلات اولیه اتصال شبکه را به‌صورت اصولی عیب‌یابی کنی.

2. سناریوی واقعی: اینترنت شرکت قطع شده است!

تصور کن به‌عنوان یک Network Engineer در یک شرکت استخدام شده‌ای.

صبح یکی از کارمندان به تو اطلاع می‌دهد:

«کامپیوتر من به شبکه وصله، ولی اینترنت ندارم.»

در همان زمان:

  • کامپیوتر همکارش اینترنت دارد.
  • پرینتر شبکه قابل دسترسی است.
  • چراغ پورت شبکه روی کامپیوتر روشن است.
  • مرورگر نمی‌تواند وب‌سایت‌ها را باز کند.

اولین واکنش تو نباید Restart کردن مودم یا تغییر تصادفی تنظیمات باشد.

یک مهندس شبکه باید بتواند مشکل را مرحله‌به‌مرحله محدود کند.

برای این کار ابتدا باید بفهمیم شبکه چیست و کامپیوترها چطور با یکدیگر ارتباط برقرار می‌کنند.

3. شبکه کامپیوتری چیست؟

Computer Network مجموعه‌ای از دستگاه‌های متصل به یکدیگر است که می‌توانند داده و منابع را با یکدیگر به اشتراک بگذارند.

این دستگاه‌ها ممکن است شامل موارد زیر باشند:

  • Desktop Computers
  • Laptops
  • Servers
  • Smartphones
  • Printers
  • Routers
  • Switches
  • IoT Devices

هر دستگاهی که بتواند در یک شبکه ارتباط برقرار کند، می‌تواند یک Network Node محسوب شود.

3.1 چرا به شبکه نیاز داریم؟

شبکه‌ها برای اهداف مختلفی ساخته می‌شوند:

Resource Sharing

چند کاربر می‌توانند از یک پرینتر یا فضای ذخیره‌سازی مشترک استفاده کنند.

Communication

دستگاه‌ها می‌توانند اطلاعات را با یکدیگر مبادله کنند.

Centralized Management

مدیر شبکه می‌تواند کاربران، دسترسی‌ها و منابع را از یک نقطه مدیریت کند.

Scalability

می‌توان دستگاه‌ها و سرویس‌های جدید را بدون بازطراحی کامل زیرساخت به شبکه اضافه کرد.

Automation

سیستم‌ها می‌توانند بدون دخالت مستقیم انسان با یکدیگر ارتباط برقرار کنند و عملیات مختلفی انجام دهند.

3.2 یک مثال ساده

فرض کن یک شرکت ۲۰ کامپیوتر، دو پرینتر و یک سرور دارد.

بدون شبکه، انتقال اطلاعات و استفاده مشترک از منابع دشوار خواهد بود.

اما با ایجاد شبکه:

  • تمام کامپیوترها می‌توانند به سرور متصل شوند.
  • کاربران می‌توانند فایل‌های مشترک را مشاهده کنند.
  • چند کاربر می‌توانند از پرینترهای مشترک استفاده کنند.
  • مدیر شبکه می‌تواند دسترسی‌ها را کنترل کند.

4. انواع شبکه از نظر محدوده جغرافیایی

4.1 PAN: Personal Area Network

شبکه‌ای در محدوده شخصی و بسیار کوچک.

مثال: - اتصال گوشی به هدفون Bluetooth - اتصال ساعت هوشمند به تلفن همراه

4.2 LAN: Local Area Network

شبکه‌ای در محدوده‌ای محدود مانند خانه، دفتر یا ساختمان.

مثال: - شبکه داخلی یک شرکت - شبکه کامپیوترهای یک آزمایشگاه

4.3 WLAN: Wireless Local Area Network

نوعی شبکه محلی که ارتباط آن از طریق فناوری بی‌سیم، معمولاً Wi-Fi، انجام می‌شود.

4.4 MAN: Metropolitan Area Network

شبکه‌ای که محدوده‌ای در اندازه یک شهر یا منطقه شهری را پوشش می‌دهد.

4.5 WAN: Wide Area Network

شبکه‌ای با محدوده جغرافیایی گسترده که می‌تواند چند شهر، کشور یا قاره را به یکدیگر متصل کند.

اینترنت شناخته‌شده‌ترین نمونه از یک شبکه بسیار گسترده و متصل از شبکه‌هاست.

5. اجزای اصلی یک شبکه

برای ساخت یک شبکه، به مجموعه‌ای از تجهیزات و نرم‌افزارها نیاز داریم.

5.1 End Devices

دستگاه‌هایی که در شبکه داده تولید یا دریافت می‌کنند.

مثال: - کامپیوتر - سرور - لپ‌تاپ - تلفن همراه

5.2 Network Interface Card (NIC)

کارت یا رابط شبکه، امکان اتصال دستگاه به شبکه را فراهم می‌کند.

NIC می‌تواند از Ethernet یا Wi-Fi استفاده کند.

هر رابط شبکه معمولاً یک MAC Address دارد که در ارتباطات لایه دوم نقش مهمی ایفا می‌کند.

5.3 Switch

Switch دستگاهی است که دستگاه‌های مختلف را در یک شبکه محلی به یکدیگر متصل می‌کند.

سوئیچ‌های Ethernet معمولاً با استفاده از MAC Address تصمیم می‌گیرند فریم‌ها را از کدام پورت ارسال کنند.

برای مثال، اگر کامپیوتر A بخواهد به کامپیوتر B در همان شبکه محلی اطلاعات بفرستد، سوئیچ می‌تواند فریم را به پورت متصل به B ارسال کند.

5.4 Router

Router شبکه‌های IP مختلف را به یکدیگر متصل می‌کند.

وظیفه اصلی آن Forward کردن Packetها بر اساس Routing Table است.

مثلاً: - اتصال شبکه داخلی شرکت به اینترنت - اتصال دو شعبه یک شرکت - انتقال ترافیک بین VLANها در صورت پیکربندی مناسب

5.5 Access Point

Access Point امکان اتصال بی‌سیم دستگاه‌ها به شبکه را فراهم می‌کند.

گوشی یا لپ‌تاپ از طریق Wi-Fi به Access Point متصل می‌شود و در بسیاری از شبکه‌ها از آن مسیر به شبکه کابلی دسترسی پیدا می‌کند.

5.6 Server

سرور سیستمی است که سرویس یا منبعی را در اختیار کلاینت‌ها قرار می‌دهد.

مثال: - Web Server - DNS Server - DHCP Server - File Server - Database Server

6. Client و Server چگونه کار می‌کنند؟

یکی از رایج‌ترین مدل‌های ارتباطی در شبکه، Client-Server Architecture است.

در این مدل:

  • Client درخواست ارسال می‌کند.
  • Server درخواست را دریافت و پردازش می‌کند.
  • Server پاسخ را برمی‌گرداند.

مثال:

وقتی آدرس یک وب‌سایت را در مرورگر وارد می‌کنی، مرورگر نقش Client را دارد و سرور وب درخواست را دریافت می‌کند.

البته معماری شبکه همیشه Client-Server نیست. مدل Peer-to-Peer نیز وجود دارد که در آن دستگاه‌ها می‌توانند مستقیماً منابع خود را با یکدیگر به اشتراک بگذارند.

7. داده چگونه در شبکه منتقل می‌شود؟

برای انتقال اطلاعات، داده به واحدهای کوچک‌تری تقسیم می‌شود.

در شبکه‌های مختلف اصطلاحات متفاوتی داریم:

لایه یا فناوری واحد داده
Application Data
Transport Segment / Datagram
Network Packet
Data Link Frame
Physical Bits

این فرایند بخشی از مفهومی است که بعداً با نام Encapsulation به‌صورت عمیق بررسی خواهیم کرد.

در یک ارتباط معمولی، داده از سیستم مبدأ خارج می‌شود، از تجهیزات شبکه عبور می‌کند و در مقصد دوباره پردازش می‌شود.

8. یک مثال واقعی از مسیر ارتباطی

فرض کن کامپیوتر تو می‌خواهد به یک وب‌سایت روی اینترنت متصل شود.

مسیر ساده‌شده می‌تواند چنین باشد:

  1. مرورگر درخواست را ایجاد می‌کند.
  2. سیستم عامل از تنظیمات شبکه استفاده می‌کند.
  3. در صورت نیاز، نام دامنه به IP Address تبدیل می‌شود.
  4. سیستم تشخیص می‌دهد مقصد در شبکه محلی است یا خارج از آن.
  5. اگر مقصد خارج از شبکه محلی باشد، Packet به Default Gateway ارسال می‌شود.
  6. Router آن را بر اساس Routing Table به مسیر بعدی هدایت می‌کند.
  7. Packet از چند شبکه عبور می‌کند تا به مقصد برسد.
  8. سرور مقصد پاسخ را برمی‌گرداند.

این توضیح ساده‌شده است. جزئیات DNS، ARP، TCP، IP و Routing را در جلسات آینده بررسی می‌کنیم.

9. آزمایش عملی اول: شناسایی شبکه سیستم خودت

در این آزمایش از Windows PowerShell استفاده می‌کنیم.

PowerShell را باز کن و دستور زیر را اجرا کن:

ipconfig /all

اطلاعات زیر را پیدا کن:

  • نام Network Adapter
  • IPv4 Address
  • Subnet Mask
  • Default Gateway
  • DNS Servers
  • Physical Address

تحلیل خروجی

IPv4 Address

آدرس IPv4 اختصاص‌یافته به رابط شبکه است.

Subnet Mask

مشخص می‌کند کدام بخش از آدرس IP به Network Portion و کدام بخش به Host Portion مربوط است.

Default Gateway

مسیر پیش‌فرض برای ارسال ترافیک به شبکه‌های دیگر است.

DNS Server

سروری است که در تبدیل نام دامنه به IP Address به سیستم کمک می‌کند.

Physical Address

آدرس MAC رابط شبکه است.

نکته: اطلاعات خروجی را با اطلاعات دستگاه دیگری مقایسه نکن. هر Network Adapter می‌تواند تنظیمات مستقل خودش را داشته باشد.

10. آزمایش عملی دوم: بررسی ارتباط شبکه

دستورهای زیر را به‌ترتیب اجرا کن.

Test 1: بررسی TCP/IP Loopback

ping 127.0.0.1

این آدرس به Loopback Interface اشاره می‌کند.

این آزمایش برای بررسی اولیه عملکرد TCP/IP در سیستم محلی مفید است، اما سالم بودن کل کارت شبکه فیزیکی را ثابت نمی‌کند.

Test 2: بررسی ارتباط با یک IP عمومی

ping 8.8.8.8

اگر پاسخ دریافت کردی، یعنی ICMP Echo به مقصد برگشته است.

اگر پاسخی دریافت نکردی، هنوز نمی‌توان نتیجه گرفت که اینترنت قطع است؛ ممکن است ICMP در مسیر مسدود شده باشد.

Test 3: بررسی DNS

ping google.com

در این مرحله سیستم باید نام دامنه را به IP تبدیل کند.

اگر Ping به IP عمومی موفق باشد اما نام دامنه Resolve نشود، احتمال وجود مشکل DNS مطرح می‌شود.

Test 4: بررسی مسیر شبکه

tracert google.com

این دستور تلاش می‌کند مسیر عبور بسته‌ها تا مقصد را نمایش دهد.

ممکن است بعضی Routerها به درخواست‌های Traceroute پاسخ ندهند. وجود * لزوماً به معنای خرابی شبکه نیست.

Test 5: مشاهده جدول ARP

arp -a

این دستور نگاشت‌های شناخته‌شده IP به MAC Address را نمایش می‌دهد.

11. آزمایش عملی سوم: بررسی Gateway و DNS

این دستورات را اجرا کن:

Get-NetIPConfiguration

برای بررسی دسترسی به Gateway:

Test-NetConnection 192.168.1.1

آدرس را با Default Gateway واقعی سیستم خودت جایگزین کن.

برای بررسی پورت HTTPS یک سرور:

Test-NetConnection google.com -Port 443

به مقدار TcpTestSucceeded توجه کن.

اگر مقدار True باشد، اتصال TCP به پورت موردنظر برقرار شده است.

این تست به‌تنهایی سلامت کامل وب‌سایت یا کیفیت اینترنت را اثبات نمی‌کند.

12. چالش عیب‌یابی: اینترنت کار نمی‌کند!

سناریو:

یک کامپیوتر به شبکه کابلی متصل است، اما کاربر نمی‌تواند وب‌سایت‌ها را باز کند.

نتایج بررسی:

  • Link چراغ پورت روشن است.
  • IPv4 Address برابر 169.254.20.15 است.
  • Default Gateway خالی است.
  • کامپیوترهای دیگر اینترنت دارند.

سؤال اول

چه اتفاقی احتمالاً رخ داده است؟

سؤال دوم

چرا آدرس 169.254.x.x می‌تواند نشانه مشکل در دریافت تنظیمات DHCP باشد؟

سؤال سوم

برای بررسی مشکل از چه دستورهایی استفاده می‌کنی؟

راهنمایی:

ipconfig /all
ipconfig /release
ipconfig /renew

دقت کن که اجرای Release و Renew اتصال فعلی را تغییر می‌دهد. این دستورات را در محیط آزمایش یا با آگاهی از اثر آن‌ها اجرا کن.

13. Engineering Challenge

یک گزارش فنی کوتاه از شبکه سیستم خودت تهیه کن.

  1. نوع اتصال: Ethernet یا Wi-Fi
  2. نام Network Adapter
  3. IPv4 Address
  4. Subnet Mask
  5. Default Gateway
  6. DNS Server
  7. نتیجه Ping به Loopback
  8. نتیجه بررسی یک IP عمومی
  9. نتیجه بررسی DNS
  10. نتیجه Traceroute

در پایان گزارش، توضیح بده که آیا سیستم تو می‌تواند با شبکه محلی و اینترنت ارتباط برقرار کند یا خیر.

قانون مهم: هیچ‌وقت فقط بر اساس یک تست، درباره سلامت کل شبکه نتیجه‌گیری نکن.
