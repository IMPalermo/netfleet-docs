Introduction to Computer Networks

Week 01 · Day 01

مبانی شبکه‌های کامپیوتری، معماری ارتباطات و انتقال داده

جلسه اول: آشنایی با شبکه‌های کامپیوتری

1. شبکه کامپیوتری چیست؟

شبکه کامپیوتری (Computer Network) مجموعه‌ای از دستگاه‌های مستقل است که از طریق یک بستر ارتباطی به یکدیگر متصل شده‌اند تا بتوانند اطلاعات، منابع و سرویس‌ها را به اشتراک بگذارند.

این دستگاه‌ها می‌توانند شامل موارد زیر باشند:

  • کامپیوترهای شخصی
  • لپ‌تاپ‌ها و تلفن‌های همراه
  • سرورها
  • پرینترهای شبکه
  • روترها و سوئیچ‌ها
  • تجهیزات اینترنت اشیا (IoT)

برای مثال، وقتی از لپ‌تاپ خود وارد یک وب‌سایت می‌شوید، دستگاه شما باید بتواند با سروری در نقطه‌ای دیگر از جهان ارتباط برقرار کند. این ارتباط از طریق مجموعه‌ای از تجهیزات، پروتکل‌ها و استانداردهای شبکه انجام می‌شود.

چرا شبکه به وجود آمد؟

فرض کنید در یک شرکت ۳۰ کامپیوتر وجود دارد. اگر شبکه‌ای وجود نداشته باشد، انتقال فایل بین کامپیوترها، استفاده مشترک از پرینتر و دسترسی به سرور مرکزی بسیار دشوار خواهد بود.

شبکه این مشکلات را حل می‌کند:

  1. اشتراک‌گذاری منابع
  2. انتقال اطلاعات
  3. ارتباط بین کاربران
  4. مدیریت متمرکز سیستم‌ها
  5. دسترسی به سرویس‌های راه دور
  6. افزایش مقیاس‌پذیری زیرساخت

نکته مهندسی: شبکه فقط اتصال چند کامپیوتر به یکدیگر نیست. شبکه یک زیرساخت ارتباطی است که سرویس‌های نرم‌افزاری و سیستم‌های سازمانی روی آن فعالیت می‌کنند.

2. انواع شبکه بر اساس محدوده جغرافیایی

شبکه‌ها را می‌توان بر اساس محدوده پوشش جغرافیایی دسته‌بندی کرد.

LAN - Local Area Network

شبکه محلی، شبکه‌ای است که محدوده جغرافیایی کوچکی را پوشش می‌دهد.

مثال‌ها:

  • شبکه یک خانه
  • شبکه یک شرکت
  • شبکه یک آزمایشگاه دانشگاه
  • شبکه یک طبقه از ساختمان

ویژگی‌های رایج:

  • محدوده جغرافیایی محدود
  • مدیریت نسبتاً ساده‌تر
  • استفاده از Ethernet یا Wi-Fi
  • امکان اشتراک‌گذاری منابع محلی

WAN - Wide Area Network

شبکه گسترده، شبکه‌ای است که مناطق جغرافیایی بزرگ را به یکدیگر متصل می‌کند.

مثال:

فرض کنید یک شرکت در تهران، اصفهان و شیراز دفتر دارد. برای ارتباط شبکه‌ای بین این شعبه‌ها می‌توان از زیرساخت WAN استفاده کرد.

ویژگی‌های رایج:

  • پوشش جغرافیایی گسترده
  • اتصال شبکه‌های مستقل
  • استفاده از زیرساخت اپراتورها
  • نیاز به مسیریابی بین شبکه‌ها

MAN - Metropolitan Area Network

شبکه‌ای با محدوده پوشش در سطح یک شهر یا منطقه شهری است.

برای مثال، یک شبکه ارتباطی که چند ساختمان یک سازمان را در نقاط مختلف یک شهر متصل می‌کند.

مقایسه

نوع محدوده معمول مثال
PAN شخصی اتصال موبایل به ساعت هوشمند
LAN ساختمان یا محیط محدود شبکه شرکت
MAN شهر شبکه شهری
WAN مناطق گسترده ارتباط شعب شرکت

نکته: این دسته‌بندی‌ها محدوده‌های مفهومی هستند و مرز فیزیکی کاملاً ثابتی ندارند.

3. اینترنت دقیقاً چیست؟

Internet یک شبکه عظیم متشکل از شبکه‌های مستقل است.

به همین دلیل از عبارت Network of Networks برای توصیف اینترنت استفاده می‌شود.

میلیون‌ها شبکه در سراسر جهان از طریق تجهیزات و پروتکل‌های استاندارد با یکدیگر ارتباط برقرار می‌کنند.

اینترنت متعلق به یک کامپیوتر یا یک سازمان واحد نیست. شبکه‌های مختلف توسط سازمان‌ها، شرکت‌ها، اپراتورها و ارائه‌دهندگان خدمات اینترنت مدیریت می‌شوند.

تفاوت Internet و Web

این دو مفهوم یکسان نیستند.

Internet: زیرساخت ارتباطی جهانی است.

World Wide Web: مجموعه‌ای از صفحات و منابعی است که از طریق اینترنت و عمدتاً با پروتکل HTTP و HTTPS در دسترس هستند.

برای مثال:

  • ایمیل می‌تواند از اینترنت استفاده کند.
  • بازی آنلاین از اینترنت استفاده می‌کند.
  • تماس VoIP از اینترنت استفاده می‌کند.
  • وب‌سایت‌ها از طریق Web در اینترنت قابل دسترسی هستند.

بنابراین Web فقط یکی از سرویس‌های قابل ارائه روی اینترنت است.

4. Client و Server

یکی از مهم‌ترین مدل‌های ارتباطی در شبکه، معماری Client-Server است.

Client چیست؟

Client دستگاه یا نرم‌افزاری است که برای دریافت یک سرویس به سیستم دیگری درخواست ارسال می‌کند.

مثال:

  • مرورگر Chrome
  • اپلیکیشن موبایل
  • نرم‌افزار مدیریت شبکه
  • کلاینت SSH

Server چیست؟

Server سیستم یا نرم‌افزاری است که درخواست‌ها را دریافت کرده و سرویس موردنظر را ارائه می‌دهد.

مثال:

  • Web Server
  • DNS Server
  • Database Server
  • File Server
  • DHCP Server

یک مثال واقعی

فرض کنید آدرس یک وب‌سایت را در مرورگر وارد می‌کنید.

  1. مرورگر درخواست لازم را آماده می‌کند.
  2. دستگاه شما اطلاعات مقصد را مشخص می‌کند.
  3. درخواست از طریق شبکه ارسال می‌شود.
  4. سرور درخواست را دریافت می‌کند.
  5. سرور پاسخ مناسب را تولید می‌کند.
  6. پاسخ از طریق شبکه به دستگاه شما بازمی‌گردد.
  7. مرورگر محتوا را نمایش می‌دهد.
Note

Client و Server الزاماً دو دستگاه فیزیکی جدا نیستند. یک کامپیوتر می‌تواند در یک ارتباط Client و در ارتباط دیگری Server باشد.

5. تجهیزات اصلی شبکه

برای ساخت یک شبکه، تجهیزات مختلفی مورد استفاده قرار می‌گیرند.

Network Interface Card (NIC)

کارت شبکه، رابطی است که امکان اتصال یک دستگاه به شبکه را فراهم می‌کند.

هر رابط شبکه می‌تواند یک آدرس سخت‌افزاری به نام MAC Address داشته باشد.

NIC ممکن است به شکل زیر باشد:

  • Ethernet Adapter
  • Wireless Adapter
  • Virtual Network Adapter

Switch

سوئیچ دستگاهی است که معمولاً برای اتصال تجهیزات داخل یک شبکه محلی استفاده می‌شود.

سوئیچ Ethernet در لایه دوم مدل OSI فعالیت می‌کند و برای انتقال فریم‌ها از جدول MAC Address استفاده می‌کند.

برای مثال، اگر چند کامپیوتر در یک اتاق داشته باشیم، می‌توانیم آن‌ها را به یک سوئیچ متصل کنیم.

Router

روتر دستگاهی است که شبکه‌های مختلف را به یکدیگر متصل می‌کند.

روتر برای انتقال Packetها بین شبکه‌ها از اطلاعات مسیریابی استفاده می‌کند.

برای مثال، روتر خانه شما می‌تواند شبکه داخلی خانه را به شبکه ارائه‌دهنده اینترنت متصل کند.

Access Point

Access Point امکان اتصال بی‌سیم دستگاه‌ها به شبکه را فراهم می‌کند.

دستگاه‌هایی مانند موبایل و لپ‌تاپ می‌توانند از طریق Wi-Fi به آن متصل شوند.

Modem

Modem برای برقراری ارتباط با برخی فناوری‌های دسترسی به اینترنت مورد استفاده قرار می‌گیرد.

نوع مودم به فناوری ارتباطی وابسته است؛ مانند DSL یا Cable.

نکته: در بسیاری از تجهیزات خانگی، مودم، روتر، سوئیچ و Access Point در یک دستگاه ترکیب شده‌اند.

6. Packet چیست؟

یکی از مفاهیم بنیادی شبکه، Packet است.

وقتی اطلاعاتی از یک دستگاه به دستگاه دیگر ارسال می‌شود، داده‌ها می‌توانند به واحدهای کوچک‌تری تقسیم شوند.

این واحدها در لایه‌های مختلف شبکه ساختارهای مشخصی دارند.

برای مثال، در ارتباط مبتنی بر TCP/IP:

  • Application Data: داده تولیدشده توسط برنامه
  • TCP Segment: داده به‌همراه اطلاعات TCP
  • IP Packet: بسته شامل اطلاعات IP
  • Ethernet Frame: فریم قابل انتقال در شبکه محلی

این فرایند Encapsulation نام دارد.

Encapsulation

هر لایه اطلاعات کنترلی موردنیاز خود را به داده اضافه می‌کند.

نمای ساده:

Application Data ↓ TCP Segment ↓ IP Packet ↓ Ethernet Frame ↓ Physical Transmission

در مقصد، فرایند معکوس انجام می‌شود که Decapsulation نام دارد.

چرا Packetها مهم هستند؟

چون شبکه‌ها معمولاً داده‌های بزرگ را به‌صورت یک جریان یکپارچه و بدون ساختار ارسال نمی‌کنند.

تقسیم داده به واحدهای مناسب، مدیریت انتقال، مسیریابی و کنترل ارتباط را ممکن می‌کند.

7. Network Topology

Topology به ساختار اتصال تجهیزات در یک شبکه گفته می‌شود.

Star Topology

در این ساختار تمام دستگاه‌ها به یک نقطه مرکزی مانند Switch متصل می‌شوند.

مزایا: - مدیریت ساده - عیب‌یابی نسبتاً آسان - خرابی یک کابل معمولاً فقط یک دستگاه را تحت تأثیر قرار می‌دهد.

محدودیت: - خرابی دستگاه مرکزی می‌تواند ارتباط تعداد زیادی از دستگاه‌ها را قطع کند.

Bus Topology

در این ساختار چند دستگاه از یک مسیر ارتباطی مشترک استفاده می‌کنند.

این توپولوژی بیشتر جنبه تاریخی و آموزشی دارد و در شبکه‌های مدرن Ethernet کمتر استفاده می‌شود.

Ring Topology

در این ساختار دستگاه‌ها به شکل حلقه به یکدیگر متصل می‌شوند.

Mesh Topology

در ساختار Mesh چندین مسیر ارتباطی بین تجهیزات وجود دارد.

مزیت اصلی آن افزایش افزونگی (Redundancy) و امکان استفاده از مسیرهای جایگزین است.

توپولوژی یک شبکه سازمانی ساده

                 Internet
                    |
                  Router
                    |
                  Switch
             /      |      \
            /       |       \
          PC-1    Server    PC-2
                    |
                Access Point
                    |
              Laptop / Mobile

8. پروتکل چیست؟

پروتکل مجموعه‌ای از قوانین و استانداردهاست که نحوه ارتباط بین دستگاه‌ها را مشخص می‌کند.

بدون پروتکل مشترک، دستگاه‌ها نمی‌توانند اطلاعات را به شکلی قابل فهم برای یکدیگر تبادل کنند.

برخی پروتکل‌های مهم:

Protocol کاربرد
IP آدرس‌دهی و انتقال بین شبکه‌ها
TCP انتقال قابل اعتماد داده
UDP انتقال داده بدون تضمین تحویل
HTTP انتقال محتوای وب
HTTPS ارتباط امن وب
DNS تبدیل نام دامنه به اطلاعات آدرس
DHCP تخصیص خودکار تنظیمات شبکه
SSH دسترسی امن از راه دور
ARP یافتن MAC مربوط به IPv4 در شبکه محلی

در جلسات آینده هرکدام از این مفاهیم را عمیق‌تر بررسی می‌کنیم.

9. یک ارتباط واقعی از ابتدا تا انتها

فرض کنید لپ‌تاپ شما به Wi-Fi خانه متصل است و می‌خواهید وارد یک وب‌سایت شوید.

در پشت صحنه چه اتفاقی می‌افتد؟

  1. دستگاه شما از تنظیمات شبکه خود استفاده می‌کند.
  2. در صورت نیاز، DNS برای یافتن آدرس مقصد مورد استفاده قرار می‌گیرد.
  3. سیستم مشخص می‌کند مقصد در شبکه محلی است یا خارج از آن.
  4. اگر مقصد خارج از شبکه محلی باشد، Packet به سمت Default Gateway ارسال می‌شود.
  5. روتر Packet را به سمت شبکه بعدی هدایت می‌کند.
  6. Packet ممکن است از چندین Router در مسیر عبور کند.
  7. سرور مقصد درخواست را دریافت می‌کند.
  8. پاسخ به سمت دستگاه شما بازمی‌گردد.

این توضیح یک تصویر کلی است. جزئیات DNS، ARP، Routing، NAT و TCP در جلسات بعدی بررسی خواهند شد.

10. نگاه مهندسی: چرا این مفاهیم برای Network Automation مهم هستند؟

هدف ما فقط یادگیری شبکه نیست. مقصد شغلی ما Network Automation Engineering است.

فرض کنید در یک شرکت ۱۰۰ روتر و سوئیچ وجود دارد.

مدیر شبکه باید:

  • وضعیت تجهیزات را بررسی کند.
  • تنظیمات دستگاه‌ها را دریافت کند.
  • نسخه پشتیبان تهیه کند.
  • خطاهای شبکه را تشخیص دهد.
  • تغییرات پیکربندی را اعمال کند.
  • از یکسان بودن تنظیمات اطمینان حاصل کند.

انجام دستی تمام این کارها زمان‌بر و مستعد خطاست.

در آینده از Python، SSH، APIs، Ansible و ابزارهای مدیریت شبکه برای خودکارسازی این وظایف استفاده خواهیم کرد.

اما یک قانون مهم وجود دارد:

قبل از خودکارسازی یک فرایند، باید منطق فنی آن را بفهمیم.

اگر ندانیم Router چگونه Packet را مسیریابی می‌کند، نوشتن اسکریپتی برای مدیریت روترها صرفاً اتوماسیون بدون درک خواهد بود.

بخش عملی: اولین آزمایش شبکه

در این تمرین از PowerShell ویندوز استفاده می‌کنیم.

تمرین ۱: مشاهده تنظیمات شبکه

PowerShell را باز کن و دستور زیر را اجرا کن:

ipconfig /all

موارد زیر را پیدا کن:

  • IPv4 Address
  • Subnet Mask
  • Default Gateway
  • Physical Address
  • DNS Servers

این اطلاعات نشان می‌دهند دستگاه تو چگونه در شبکه شناسایی و مسیریابی می‌شود.

تمرین ۲: بررسی ارتباط با Gateway

ابتدا آدرس Default Gateway را پیدا کن.

سپس دستور زیر را با آدرس واقعی Gateway خودت اجرا کن:

ping 192.168.1.1

آدرس بالا فقط نمونه است و ممکن است با شبکه تو متفاوت باشد.

اگر پاسخ دریافت کردی، یعنی مقصد به درخواست ICMP پاسخ داده است.

البته پاسخ نگرفتن لزوماً به معنای قطع بودن شبکه نیست، چون ممکن است ICMP مسدود شده باشد.

تمرین ۳: بررسی مسیر ارتباطی

دستور زیر را اجرا کن:

tracert 8.8.8.8

این دستور تلاش می‌کند مسیر عبور Packetها تا مقصد را نمایش دهد.

هر ردیف معمولاً نمایانگر یک Hop است.

اگر بعضی ردیف‌ها ستاره نشان دادند، ممکن است تجهیزات میانی به پیام‌های مورد استفاده برای این بررسی پاسخ ندهند.

تمرین ۴: بررسی DNS

دستور زیر را اجرا کن:

nslookup google.com

خروجی نشان می‌دهد کدام DNS Server به درخواست تو پاسخ داده و چه اطلاعاتی درباره نام دامنه برگردانده است.
